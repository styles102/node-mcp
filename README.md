# node-mcp

A training project for building MCP (Model Context Protocol) servers with Node.js and TypeScript.

## Stack

- Node.js with ES modules (`"type": "module"`)
- TypeScript (`NodeNext` module mode)
- [`@modelcontextprotocol/sdk`](https://github.com/modelcontextprotocol/typescript-sdk) — official MCP TypeScript SDK
- [Zod](https://zod.dev) — input/output schema validation

## Project Structure

```
node-mcp/
├── index.ts          # Server entry point
├── dist/             # Compiled output (generated by tsc)
├── tsconfig.json
└── package.json
```

## Getting Started

```bash
pnpm install
pnpm build
pnpm start
```

The server communicates over stdio and won't produce visible output when run directly — it waits for JSON-RPC messages from an MCP client.

## Testing with MCP Inspector

```bash
pnpm exec mcp-inspector node dist/index.js
```

Open the URL printed in the terminal to access the browser-based inspector. From there you can browse registered tools and call them manually.

## Key Concepts

### Server setup

Every MCP server follows three steps:

1. Create an `McpServer` instance with a name and version
2. Register tools (and optionally resources and prompts)
3. Connect a transport and start listening

### Transports

- **stdio** — used for local servers spawned as child processes (Claude Desktop, Claude Code, MCP Inspector)
- **Streamable HTTP** — used for remote servers accessible over a network

### Tool anatomy

```ts
server.registerTool(
  'tool-name',            // identifier used by the AI client
  {
    description: '...',   // shown to the AI to help it decide when to use the tool
    inputSchema: { ... }, // zod schema — validated before your handler runs
    outputSchema: { ... } // optional — enables structuredContent in the response
  },
  async (inputs) => {
    return {
      content: [{ type: 'text', text: '...' }], // always required
      structuredContent: { ... }                 // optional, must match outputSchema
    }
  }
)
```

### ES module import paths

With `"module": "NodeNext"` in tsconfig, imports require explicit `.js` extensions even in `.ts` source files:

```ts
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
```
